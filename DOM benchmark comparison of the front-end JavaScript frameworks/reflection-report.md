# Reflection report

Building comparable applications across four frameworks required more care than copying the same list template. Each has a different update lifecycle: React commits state through its renderer, Vue batches reactive changes until `nextTick`, Svelte flushes compiled updates through `tick`, and Angular signals schedule change detection. The benchmark uses shared data, awaits each framework’s commit, and forces document layout before stopping the timer. It reports three-sample medians from production builds; task generation and display refresh are excluded.

The architecture shaped both implementation and performance. React uses keyed components, Vue uses `v-for` with stable keys, Svelte uses keyed `{#each}` blocks, and Angular uses `*ngFor` with a tracking function. All render the same task content and controls and update or remove 50 rows from a 1,000-row baseline. Building four comparable versions and accounting for their different commit timing were the main challenges; machine load, development overlays, and browser versions can also distort results.

In this run, React had the lowest median at 100 and 1,000 rows and for updating 50; Vue was quickest at 500 rows and tied React on deletion. Angular and Svelte were slower in these particular measurements, while Vue's post-run heap reading exceeded React's. This does not establish a universal winner: reconciliation cost, implementation details, browser state, and the single device all affect results, and heap snapshots include runtime overhead. The benchmark shows why realistic workload tests matter more than framework reputation. Repeating the suite on the submission device and reporting its browser and operating system would strengthen the comparison; different application components or interactions could change the outcome.
